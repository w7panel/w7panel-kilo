# 218 经 212 访问 VPC 数据库

218 Pod 需要访问 `10.0.0.15:3306` 和 `10.0.0.17:3306`。212 和 218 的 Pod `10.42.0.0/16`、Service `10.43.0.0/16`、Kilo `10.4.0.0/16` 网段重叠。不要互相宣告完整集群网段，也不要在 212 节点运行会添加 218 Pod 路由的 `kgctl connect`。

使用 212 `server1` 上独立的 WireGuard 接口 `wg-db212`，只接受 218 单节点来源 `10.200.200.2/32` 并转发到两个数据库 TCP 3306。218 Kilo Peer 只宣告数据库的两个 `/32`。具体操作、验证和回滚见 [212 数据库网关操作手册](references/212-vpc-database-gateway.md)。

执行前复核节点地址、数据库 IP、端口、出口网卡和路由。文中的地址是 2026-10-26 的现场值，不作为其他集群默认值。212 的主机和安全组操作由该机器的操作者执行；没有实际集群变更授权时，只准备清单与命令。不要把 WireGuard 私钥、数据库密码、kubeconfig 或 MCP 令牌写入仓库或聊天记录。

验收以 **218 Pod 分别连接两个数据库原内网 IP 的 TCP 3306** 为准。握手成功还需检查 212 隧道源地址、VPC 出口 SNAT 与数据库回程。若源地址不是 `10.200.200.2`，停止并排查 218 Cilium 出站伪装；不要把 212 的重叠 Pod 网段路由改指向隧道。
